# Offline Pi Wi-Fi and show service: source check

Date: 2026-09-25. Scope: [issue 42](https://github.com/garrett-reynolds/water-jet-follower/issues/42). This is a source check and a plan for the Pi build. It is not a test on the Pi. No Wi-Fi password is set here.

## Wi-Fi network

- Raspberry Pi OS Trixie uses NetworkManager. Raspberry Pi OS has used it by default since Bookworm. The Pi 5 built-in radio can host a Wi-Fi network. Set the correct WLAN country first or the radio can stay off. [Raspberry Pi OS](https://www.raspberrypi.com/documentation/computers/os.html), [Raspberry Pi network guide](https://www.raspberrypi.com/documentation/computers/configuration.html#host-a-wireless-network-from-your-raspberry-pi), [WLAN country guide](https://www.raspberrypi.com/documentation/computers/configuration.html#enable-wireless-networking-set-wlan-country)
- Use a NetworkManager access-point profile on `wlan0`. The supported `nmcli device wifi hotspot` action makes and starts that profile. Check the radio and driver on the real Pi. Set `connection.autoconnect yes`. Give the access-point profile the top `connection.autoconnect-priority` on `wlan0`, or remove other Wi-Fi profiles from auto start. Auto start picks a suitable profile; it does not replace one that is already active. A manually stopped profile can need a new `nmcli connection up` action. [NetworkManager nmcli](https://networkmanager.dev/docs/api/latest/nmcli.html), [connection settings](https://networkmanager.dev/docs/api/latest/settings-connection.html)
- Use `ipv4.method shared` for the access-point profile. This method gives the Pi a local IPv4 address and runs DHCP and a DNS forwarder for clients. DHCP gives each iPad an address. Without a set address, NetworkManager picks a `10.42.x.0/24` subnet. Set one `ipv4.addresses` value for a stable page URL. Set `ipv4.shared-dhcp-range` only if a fixed client pool is needed. Check that `dnsmasq` is on the Pi, since this method needs it. This method can forward to an upstream network when one exists, but the local page must not need one. [NetworkManager IPv4 settings](https://networkmanager.dev/docs/api/latest/settings-ipv4.html), [shared-mode example and dnsmasq note](https://networkmanager.dev/docs/api/latest/nmcli-examples.html)
- A DNS forwarder does not by itself give the Pi a useful name on an offline network. The Pi guide supports a `.local` name through mDNS (local name service). That is a separate path. Use the fixed local IPv4 address as the sure page address. Check the chosen `.local` name on the real iPad before using it as the main address. [Raspberry Pi hostname guide](https://www.raspberrypi.com/documentation/computers/configuration.html#change-the-hostname)
- The iPad can auto join only a known network. Its Auto-Join setting can be off. Apple says an iPad can show a no-internet notice on a Wi-Fi network. That notice does not prove the Pi page is down. After a Pi restart, check that the iPad has joined the Pi network, then open the local address in Safari. If another app asks for local-network access, allow it in iPad settings. Do not assume that an iPad will always rejoin without a real test. [Apple Auto-Join guide](https://support.apple.com/en-us/102480), [Apple no-internet guide](https://support.apple.com/en-gb/102554), [Apple local-network guide](https://support.apple.com/en-gb/102229)

## Show service

- Use one system service for `tracker.run show`. Use `[Install] WantedBy=multi-user.target` and enable it to start at boot. Use `After=network.target` for clean stop order at shutdown. `network.target` does not say that the access point has an address. Do not use `network-online.target` as proof that the iPad can reach this page. The viewer binds to `0.0.0.0:8080`, so it can start before the Wi-Fi address comes up. [systemd unit man page](https://manpages.debian.org/trixie/systemd/systemd.unit.5.en.html), [systemd network guide](https://systemd.io/NETWORK_ONLINE/), [project viewer](../../tracker/viewer.py)
- Check the real `olad.service` unit name on the Pi. Then use `Wants=olad.service` and `After=olad.service` if that unit exists. `After=` sets order. `Wants=` asks systemd to start the other unit. Neither proves that the DMX device is ready. The app must send and read back a full zero frame before it can start the show. [systemd unit man page](https://manpages.debian.org/trixie/systemd/systemd.unit.5.en.html), [project DMX path](../../tracker/dmx.py)
- Use `Type=exec`, `Restart=on-failure`, and a short `RestartSec=` pause. A failed command in `ExecStartPre=` blocks `ExecStart=`. `ExecStopPost=` runs after a failed start and during a restart. Use it for a best-effort zero send, but keep zero proof in the app start path. `Restart=on-failure` does not restart a clean exit or a stop that systemd asked for. [systemd service man page](https://manpages.debian.org/trixie/systemd/systemd.service.5.en.html)
- Set `StartLimitIntervalSec=` and `StartLimitBurst=` so a repeat fault does not cause an endless fast restart loop. When the limit is hit, systemd stops auto starts. The unit has a failed state. Use `systemctl status` and `journalctl -u` to find the cause. Fix it before `systemctl reset-failed` and a manual start. Do not set the limit to zero. [systemd unit man page](https://manpages.debian.org/trixie/systemd/systemd.unit.5.en.html), [Debian journalctl man page](https://manpages.debian.org/trixie/systemd/journalctl.1.en.html)
- Use `User=` for the Pi account that owns the show files. Do not run the show as root by default. Set `WorkingDirectory=` to that account's home. Use full paths for Python, the profile, and the baseline in `ExecStart=`. Check this account's access to OLA and the needed files on the real Pi. Set `StandardOutput=journal` and `StandardError=journal`, then read the unit log with `journalctl -u`. [systemd exec man page](https://manpages.debian.org/trixie/systemd/systemd.exec.5.en.html), [project run steps](../../README.md)

## Water-off rule

The present `show` command loads the last saved profile. It starts in live mode unless it gets `--lights-only`. The service must pass `--lights-only` on **every** boot and auto restart. That option holds all fountain-height channels at zero until an operator turns Lights only off on the Settings page. The app's `safe_output` first sends 512 zero slots and reads them back from OLA. It will not start the show if this check fails. The exit path tries zero again. [show start](../../tracker/run.py), [mode control](../../tracker/settings.py), [zero proof](../../tracker/dmx.py)

This is a software restart rule. The jet units can keep their last value if `olad` dies, DMX stops, the interface is removed, or the process is killed without a clean exit. In those cases a zero command cannot prove water off. The 24 V power cut is the available physical stop. The separate hardware-stop ticket covers a watchdog contactor. [project limits](../../README.md), [project stop path](../../tracker/dmx.py)
